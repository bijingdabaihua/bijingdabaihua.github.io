[Prism](https://bijingdabaihua.github.io/Prism/) 是我用 TypeScript + WGSL 从零写的 WebGPU 路径追踪器。它不依赖 three.js，也没有现成的 BVH 库：场景怎么组织、光线怎么求交、采样怎么分配，都是自己定的。

这篇文章记录几个真正花时间的设计决定，以及它们背后的取舍。

## 先定边界：主线程不碰 GPU

Prism 的主线程只做三件事：路由、UI、把用户输入翻译成相机参数。`GPUDevice`、场景编译、渲染循环全部在 Worker 里，Worker 持有一个 `OffscreenCanvas`，每帧把画面转成 `ImageBitmap` 推回主线程。

这样做的好处不是「架构好看」，而是主线程可以专心处理交互。场景编译（BVH、材质打包、贴图上传）是重活，放在 Worker 里不会卡住画廊和按钮。主线程和 Worker 之间只有一层很薄的 RPC：相机 set、背景 setImage / setRotation、模型 loadGltf / loadInstances、开始 listen。

场景的装配顺序也是显式的：先定机位，再装环境图和朝向，最后逐个追加几何。没有「根据包围盒自动取景」这条退路 —— 自动构图在作品集里几乎总是错的，机位本身就是场景的一部分。

## BVH：两级结构，一张扁平表

场景里有两类东西：三角面片和实例。Prism 用两级 BVH：

- **BLAS**：每个 mesh 自己的一棵三角形 BVH，多个 instance 共享；
- **TLAS**：把所有 instance 包起来的一棵顶层 BVH。

两棵树共用同一个构建函数。构建用分桶 SAH：每条轴切 16 个桶，按「面积 × 数量」估代价，选最便宜的切法；深度超过 40 层就退回中位数切分，因为 shader 的遍历栈只有 64 层。叶子最多放两个图元。

存到 GPU 上时，节点被压成一张扁平的 `Float32Array`，每个节点 8 个 float：

```ts
// [minX, minY, minZ, maxX, maxY, maxZ, left, right]
// slot < 0  → 图元，下标 -(slot + 1)
// slot > 0  → 子节点，偏移 nodeIndex * 8 + 1
// slot == 0 → 空
```

没有单独的「叶子标志位」：两个槽各自判断，都指向图元就是叶子。TLAS 和 BLAS 的节点最后合并成一张表，shader 只拿一个 buffer 绑定。这个格式很朴素，但遍历时不需要分支判断节点类型，缓存也友好。

## 采样：NEE + MIS

路径追踪的噪声主要来自「随机碰到光源」这件事。只靠 BSDF 采样，小光源很难被击中；只靠光源采样，粗糙表面的高光又会失真。

Prism 同时做两件事：

1. **NEE**：每个着色点直接向光源采样，环境图则按亮度 CDF 做重要性采样；
2. **MIS**：把直接光采样和 BSDF 采样的结果按概率密度加权组合，避免重复计算能量。

环境图会先在 CPU 上算一张亮度 CDF，采样时按亮度选行、再在行内选列。这样日落这种「大部分区域很暗、太阳很亮」的环境图，不会把样本浪费在无关的天空上。

代码上，这一块最容易被忽略的是**概率密度的一致性**：光源采样、环境采样、BSDF 采样必须用同一套立体角度量，否则 MIS 的权重会悄悄错掉，画面看起来「差不多」，但能量不对。

## 渐进累积：用时间换质量

Prism 不是一帧出图，而是持续累积。

像素顺序是 `0..W*H-1` 的随机排列，每帧取连续一段。一轮下来每个像素正好被采一次，把每轮的样本平均起来，噪声就随轮数下降。相机一动，累积清零，从第一轮重来；场景不变时，画面会一直变干净。

每帧 dispatch 多少像素不是写死的，而是根据 GPU timestamp 实测的上一帧耗时调整，下限 4096 像素。这样拖动相机时不会因为预算太大而卡顿，静止时又能尽快把预算拉满。

这套机制和「瓦片渲染」不是一回事：没有 tile 的概念，只有一条全局的随机像素序列。好处是实现简单、负载均匀；代价是不能只重绘屏幕上的某一块。

## 材质与位移：把复杂性留在 CPU

材质被压成固定 28 个 float（112 字节）的 SSBO，只打包 shader 真正读的字段：baseColor、metallic、roughness、normalScale、occlusionStrength，以及五组贴图引用。贴图按类型进四个 `texture_2d_array`，每层 1024²、带完整 mip 链、16 层；同一张 `Image` 对象只占一层。

glTF 的 metallicRoughness 打包图直接进 roughness 数组（G = 粗糙度，B = 金属度），不额外开绑定。Poly Haven 的 ARM 图也是同一套通道排列。

位移是另一个例子。位移贴图是材质字段，但进 GPU 之前它必须消失：`Mesh.evolve()` 按 `displacementScale` 把三角形细分成重心坐标网格，按高度图抬起顶点，再按高度场梯度重算法线。之后着色器完全不知道位移贴图存在，材质 SSBO 里也没有这一格。

代价是场景加载会变慢 —— 荒地场景的地面细分是加载时间的大头。这是目前最明确的优化方向，但先把画面调好更重要。

## 还没做完的事

Prism 现在能稳定渲染 PBR + glTF + 位移场景，但离「完整」还有距离：

- **玻璃 / 透射**还没做，材质只有金属度 / 粗糙度这一套；
- **景深**已经接进相机，但目前为了调材质先关着；
- **场景加载**偏慢，位移细分和贴图解码都有优化空间；
- 只有一张场景，缺少更复杂的室内光路和更多资产来压测。

下一步会先补材质模型和场景，再回头处理加载性能。画面质量优先于收敛速度 —— 画廊里的图可以整夜累积，先好看，再谈快。
